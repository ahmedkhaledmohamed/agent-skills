# Portable specification workflow

## Problem Framing

A team with many software and data assets needs a portable way to establish what it owns, document current behavior and intended requirements, and identify development gaps against changing goals. Existing prose alone does not provide a reliable coverage denominator or source-change review process.

## Approach

Added one reusable skill with focused references for the operating model, artifact types, source change loop, and installation in another environment. The workflow separates ownership census, observations, requirements, rollout and outcome evidence, and stakeholder needs.

## Key Decisions

Used one coordinator skill with optional scoped agent roles instead of requiring a particular agent platform or connector. The skill distinguishes an in-session review loop from a durable scheduled detector and keeps publication and requirement approval under the target environment's authority.

## Outcome

The repository now contains a portable method and example record shapes that can guide another team's spec system without carrying over any organization-specific sources or configuration.
