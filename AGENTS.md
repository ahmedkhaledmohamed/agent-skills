# Portable skill collection

Read README.md, then only the selected skill and relevant references. This repository stores reusable instructions, not live workspace configuration or source evidence.

Use a feature branch in an isolated worktree from fetched upstream. Preserve unrelated changes. Follow the owner's diff-review, contribution-record, publication and merge rules. Do not push, publish or change visibility merely because a skill was requested.

Write skills around distinct user goals with short, precise descriptions. Keep detailed examples and procedures in references when needed. Existing working documents own task state; a new skill must not create a competing tracker or require a broad workspace briefing for routine edits.

No employer-specific names, business requests, internal links, object IDs, source code, datasets, conversations, credentials, personal machine paths or account configuration belong in exports. Use independently written fictional examples. Do not copy third-party plugin resources; document dependencies and licensing instead. Public product names are acceptable when needed to identify an integration or runtime.

Run the portability checker and the affected skill/script validation before proposing publication. Automated checks do not establish that all material is safe to disclose; inspect the full diff and any history that a visibility change would expose. Report access limits and unresolved findings.
